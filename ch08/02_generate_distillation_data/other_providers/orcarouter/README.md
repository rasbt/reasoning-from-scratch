# OrcaRouter Distillation Provider

This folder contains the OrcaRouter-specific hosted generation script for chapter 8 distillation data generation.

Run the commands below from `ch08/02_generate_distillation_data/` so relative paths like `math_train_sample.json` continue to work as written.

The input and output JSON formats are the same as the ones documented in the [main README](../../README.md#input-data-format).

&nbsp;
## Files

- [generate_with_orcarouter.py](generate_with_orcarouter.py): Uses [OrcaRouter](https://www.orcarouter.ai)'s cloud API to generate the model answers for distillation. OrcaRouter is an OpenAI-compatible router that serves open-weight reasoning models (DeepSeek, Qwen, GLM, MiniMax, Kimi) as well as proprietary ones through a single endpoint and API key.

&nbsp;
## OrcaRouter setup

1. Create an account at [OrcaRouter](https://www.orcarouter.ai)
2. Generate an API key in the [console](https://www.orcarouter.ai/console) (keys start with `sk-orca-`)
3. Save the API key in a secure location (e.g., a password manager)

Model IDs keep the upstream namespace, so `deepseek/deepseek-reasoner` is passed through as-is. The full catalog is listed at [https://www.orcarouter.ai/models](https://www.orcarouter.ai/models). Reasoning models that were verified to return a separate thinking stream include:

- `deepseek/deepseek-reasoner` — DeepSeek reasoning model, 1M context window (default)
- `qwen/qwen3.5-plus` — Qwen reasoning model, 1M context window
- `z-ai/glm-5.2` — GLM reasoning model, 1M context window
- `minimax/minimax-m3` — MiniMax reasoning model, 1M context window

&nbsp;
## Data generation with OrcaRouter

The OrcaRouter script works similarly to the OpenRouter script:

```bash
ORCAROUTER_API_KEY="YOUR_API_KEY" uv run other_providers/orcarouter/generate_with_orcarouter.py \
  --math_json math_train_sample.json \
  --dataset_size 5 \
  --model deepseek/deepseek-reasoner \
  --num_processes 1 \
  --out_file sample_orcarouter_outputs.json
```

If you are not a `uv` user, replace `uv run` with `python`.

The output file has the same structure as the ones generated by the Ollama and OpenRouter scripts.

## Controlling the thinking stream

Since the distillation data is only as good as the `"message_thinking"` traces it contains, the script exposes the reasoning budget as a flag:

```bash
ORCAROUTER_API_KEY="YOUR_API_KEY" uv run other_providers/orcarouter/generate_with_orcarouter.py \
  --math_json math_train_sample.json \
  --dataset_size 5 \
  --model deepseek/deepseek-reasoner \
  --reasoning_effort high \
  --out_file sample_orcarouter_outputs.json
```

Notes:

- Accepted values are `none`, `low`, `medium`, `high`, and `xhigh`. Omit the flag to use the model default.
- `--reasoning_effort none` turns the thinking stream off entirely, so `"message_thinking"` comes back empty. That is useful for a cheap sanity check, but not for generating distillation data.
- OrcaRouter takes this as a flat, top-level `reasoning_effort` field (the OpenAI spelling), not as the nested `{"reasoning": {"effort": ...}}` object that some other routers use.
- The upstream providers do not agree on what to call the thinking stream in the response: DeepSeek, Qwen, and MiniMax return `reasoning_content`, while GLM returns `reasoning`. The script reads both, so `"message_thinking"` is populated either way.

**Note:** A few models restrict sampling parameters. For example, `kimi/kimi-k3` only accepts `--temperature 1`; the API returns an explicit error message when a model rejects a value.

## Generating a MATH-500 distillation dataset

To generate teacher answers for the 500-example MATH-500 set, you can omit `--math_json`; the OrcaRouter script automatically loads `math500_test.json` (and saves a local copy on first use).

```bash
ORCAROUTER_API_KEY="YOUR_API_KEY" uv run other_providers/orcarouter/generate_with_orcarouter.py \
  --dataset_size 500 \
  --model deepseek/deepseek-reasoner \
  --num_processes 1 \
  --out_file math500_orcarouter_distill.json
```

## Generating a distillation dataset of 12,000 MATH samples

This uses the same non-overlapping 12,000-sample training set from chapters 6, 7, and 8. If you do not have it yet, download it first:

```bash
curl -fL -o math_full_minus_math500.json \
https://raw.githubusercontent.com/rasbt/math_full_minus_math500/refs/heads/main/math_full_minus_math500.json
```

```bash
ORCAROUTER_API_KEY="YOUR_API_KEY" uv run other_providers/orcarouter/generate_with_orcarouter.py \
  --math_json math_full_minus_math500.json \
  --dataset_size 12000 \
  --model deepseek/deepseek-reasoner \
  --num_processes 50 \
  --resume \
  --out_file math12000_orcarouter_distill.json
```

For large runs, reduce or increase `--num_processes` depending on your account limits and desired throughput.

**Tip:** OrcaRouter also exposes a router alias, `orcarouter/auto`, that picks an upstream model per request. It is handy for cheap bulk calls, but it is not recommended as a distillation teacher: the alias may route to a model that does not emit a thinking stream, in which case `"message_thinking"` comes back empty for those rows. Pin an explicit model name for distillation runs.
